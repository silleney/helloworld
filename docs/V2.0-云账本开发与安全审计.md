# V2.0 第二阶段：云账本准备与安全审计

## 基线与边界

从 v2.0-pages-static / bfd4415744dfb06c41c452ddcec77582369d26a9 建立 v2.0-cloud-ledger。原 App.tsx、storage.ts、domain.ts、依赖与 lockfile、数据库、JSON 格式、manifest 和上线分支均不修改。新增模块尚未接入原首页或构建入口；本轮是可测试的云基础层，不是已经上线的云同步产品。未连接 little-ledger-dev，未执行远程 SQL，未部署或读取真实数据。

LedgerRepository 的 list/put/remove 适合本地事务，但没有 pending/conflict 状态，也没有显式操作 ID。不能直接把 getRepo 换成远程实例，否则 UI 会错误提示云保存成功或重试生成新 ID。后续独立测试页应通过 CloudSync.stage/sync 和状态展示接入现有编辑能力。现有本地模式维持原流程；云模式必须明确区分本机待同步、云端已确认和冲突。

## 架构

- ledger_private.ledgers：账本、owner、全账本修订号。当前每用户一个个人账本（owner 唯一）；将来多账本需经过新迁移移除该唯一约束，不是开发家庭功能。
- members：owner/editor/viewer；本轮只允许 RPC 建立 owner，没有客户端邀请或修改成员接口。SQL 管理员维护测试成员，不把管理权限放入浏览器。
- entries：原 V1 字段 + 服务器 revision、deleted；历史记录 ID 用 text(长度上限128)，不要求 UUID。金额整数分，日期与分类强校验；created_at/updated_at 以原字符串保留，避免 JSON 往返改变文本。修订号而非客户端时间决定冲突。
- operations：按账本、用户、操作 UUID 唯一，存请求和结果。重试同一操作返回同一结果；不同请求复用 UUID 被拒绝。先查权限再查操作结果，撤权后不能重放读取。
- 每个写批次最多1000条、约2MB；同账本串行事务，容量与总金额约束在提交内检查。冲突整批拒绝，不部分写入。
- 删除是 tombstone；create/import 不会复活；恢复需显式 restore 和当前修订号。updated_at 不用于幂等或同步排序。
- 当前读取采用一次 MVCC 全量快照，revision和rows来自同一语句；无需设计容易漏提交的增量游标。大账本以后应增加可验证分页快照，现版本只用于虚拟账目验证。

## 权限审计

所有业务表显式 ENABLE RLS。anon/PUBLIC 无私有 schema/table 权限；authenticated 只有私有 schema USAGE 和 SELECT，RLS 只允许成员读取账目、本人读取成员行、本人且仍有成员资格读取操作。没有 INSERT/UPDATE/DELETE grant 或 policy。ledger_private 不应加到 Data API exposed schemas；public 只提供3个明确授权的 RPC。必须在真实项目确认 public RPC 可见，不能因项目禁止自动暴露新表而改成暴露全部私有表。

没有创建视图，避免默认 definer 视图绕过 RLS。ll_snapshot 是 invoker，适用表权限与 RLS；ll_create_personal_ledger、ll_apply_operation 是 definer，确实以迁移管理员权限运行，不能称它们仍受用户 RLS 自动保护。它们使用空 search_path、限定 schema 名、不使用动态 SQL、显式 auth.uid()/成员角色检查、精确授权和事务版本判断。PUBLIC 默认函数 EXECUTE 被逐函数撤销，anon 无 EXECUTE；只有 authenticated 可执行。数据库管理员/平台服务密钥仍是受信任的高权限主体，本方案不防止管理员读数据，且不是端到端加密。

不要为方便加 SECURITY DEFINER 视图、任意 SQL RPC、广泛表写授权或暴露 service_role。成员表本人读取规则不查询自己所属账本，避免策略递归。现有平台自动 RLS 是附加保护，不替代本迁移策略。

## 访问层、认证和同步

src/cloud/api.ts：依赖注入项目 URL、publishable key、用户 access token；不需要新增 SDK。只接受官方 HTTPS 项目 URL 与 sb_publishable_ 前缀，拒绝 secret/JWT 服务密钥；无真实配置文件或凭证。RPC 使用用户 Bearer token，失败抛出错误，绝不转换成空账本。

auth.ts：密码登录/refresh/logout REST 基础层，令牌只在内存；没有存储密码，没有记录令牌，没有开放注册界面。必须用 auth.token(expectedAccountId) 为每个账号绑定 API，切换账号/退出时 close 旧同步实例、移除其展示状态，不删除其队列。晚到的登录/refresh不能恢复已退出会话。logout 使用 local scope，只撤销当前刷新会话，不主动登出其他设备；已签发 access JWT 可能直到到期才失效，不能承诺远程立即撤销。初期不持久化会话，重开需重新登录；未来主屏幕免重复登录和找回密码尚需安全设计及真机验证，不宣称已完成。

queue.ts：little-ledger-cloud-v1 独立 IndexedDB，按项目/账号/账本分区。输入确认时生成且持久化记录 ID 和操作 ID，再发送。离线/超时/401/权限错误保留原操作为 pending；重开后复用原请求。服务器提交但响应丢失可安全重试。ack/cache 写入失败也不丢原队列。已确认和冲突操作暂不清理，方便审计。冲突保留原操作和云快照，停止后续提交，不能自动 last-write-wins。

冲突解决界面、显式用户选择后创建新操作、独立测试登录页、离线状态 UI、备份含待同步操作的恢复工具尚未接入。不要把这一基础层当作正式产品，不导入真实账目。旧本地模式已确认保存提示不受影响。

## JSON 与灾难恢复

原 version:1 JSON 校验、字段和 planImport 保持不变。云迁移预览应按账本内 ID 比较所有原字段；相同内容跳过、同 ID 不同内容或已删除记录报告冲突；不重新分类或清洗描述。迁移使用显式导入批次和稳定操作 ID，先虚拟验证中断重试。超过一个批次不是全量原子导入，必须增加迁移批次管理后才允许真实大文件迁移；本轮不实现/宣称真实迁移完成。

备份必须同时考虑云端已确认数据、本机 pending/conflict，以及数据库权限与 tombstone。V1 JSON仍是可携带业务备份，但不包含同步元数据。不得将仅云快照导出的文件称为包含所有未同步数据的完整备份。SQL平台备份/离线SQL导出应另存，免费项目可能休眠且不提供可下载托管备份。正式使用前确定独立备份周期、权限和恢复演练。

## 部署和回滚

见 supabase/README.md。先只读 preflight，再由用户在 little-ledger-dev 明确执行单个业务迁移。迁移是事务且不删除既有对象；对象已存在时停止，不能用 DROP IF EXISTS 重试。现有 Cloudflare 生产分支不变。由于尚未确认真实 Pages 预览分支策略，本轮不推送新分支，避免自动生成云测试部署；文件留在独立本地分支供审核。

rollback-disable-cloud.sql 只撤销客户端云写入/建账权限，保留读取和全部数据；不 drop/truncate，不删除用户。先停测试客户端同步，导出测试快照，执行权限回滚，检查被拒绝和备份仍可读。恢复授权需审批诊断结果，不能盲目重跑建表。

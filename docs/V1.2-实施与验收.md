# 小账 V1.2 开发验收记录

日期：2026-10-10（北京时间）。分支 v1.2-mobile-data-safety，基于 V1.1 的 1a006a95140f706ca550d7282dbd4b78f83743da。本轮不合并 main、不部署、不覆盖 acceptance 中既有 iPhone ZIP。

## 实施

- 手机 600px 以下：首页总额及两分类在同一浅紫卡片内；压缩留白，紧接记账入口。
- 手机流水/统计统一雾蓝紫、浅底和深色文本；去掉英文装饰标题与大标题，功能性页面标题保留在顶部。统计图用 CSS 变量，桌面保留原色默认值。
- 手机输入示例改为“买菜38元，零食25元”，桌面保留原示例、布局和交互。
- 数据正在读取或读取失败时，不渲染正常金额和空账本；失败明确显示“账本未能读取，当前金额和记录数量未知”，可重试但不自动修复。备份导出禁用，设置中不宣称记录为 0。
- 数据库名称 little-ledger-v1、版本 1、entries store、记录结构、日期/分类/金额存储及 JSON/CSV 格式均未改。未修改存储层和依赖。

## 自动验证

核心测试：86 项通过。Chromium E2E：27 项通过、1 项手机专属场景在桌面按设计跳过；原有 20 项继续通过。

新增安全测试对真实 V1.0 已构建页面保存虚拟多笔账目，在同一测试来源经 Service Worker 更新到 V1.2，逐条比较 ID、描述、金额分、分类、日期、来源和时间戳；检查数据库版本仍为 1。更新时对写入/删除 API 设拒绝保护，更新后新符号解析器生效；JSON 导出并恢复到另一个全新隔离浏览器上下文，逐条一致。

读取失败测试先保存两笔虚拟账目，再模拟 getAll 失败，检查三个页面不显示正常空账本和零统计，错误明确、导出禁用；恢复测试环境中的读取方法后，只读核对数据库记录仍完全一致。

浏览器均是 Playwright 非持久隔离上下文，服务仅绑定 Linux 测试机回环地址；没有访问用户 iPhone/Safari 数据。现有单元存储测试使用随机命名 fake-indexeddb 数据库。没有执行用户数据的清理、重建或迁移。

构建：npm run build -- --target=safari15.4 通过。

截图：docs/v1.2-screenshots，覆盖 320、390、430 手机宽度的三页面（有虚拟账目）及 1440 桌面。对照 V1.1 ZIP，固定日期和不同消费日期保证记录排序稳定。桌面三页面 PNG 一致；手机无横向溢出，结合已有 375/390 等交互测试验证首屏识别入口、聚焦展开及长金额。

复现命令（开发环境，不是在 Catalina 上执行）：

```
git fetch origin acceptance-preview
npm test
npm run build -- --target=safari15.4
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npx playwright test --project=desktop --project=iphone-size --workers=2
node tests/verify-v12-screenshots.mjs
```

跨版本测试从固定 acceptance-preview 提交 ca270f6e143fe992812c7f4dee36a7a5a5d22610 读取 V1.0 静态网页；缺少该 Git 对象会明确失败，不能用新代码冒充旧版本。截图脚本只在临时文件夹解压既有 ZIP，不改动该 ZIP。

## 发布阻塞与真实设备限制

DATA-001 仍未解决，见 RELEASE-BLOCKERS.md，阻塞正式发布。这些自动验证不证明原 iPhone 账目仍在，也不证明 Safari/iOS 的回收、存储分区、主屏幕和普通/无痕容器行为与 Chromium 相同。WebKit 未安装，没有声称 Safari 自动化通过。

## 下一步 iPhone 13 真机验收（待确认后准备独立测试入口）

现在不要替换原 https://192.168.0.156:8443 的页面，也不要在原来源新增、删除或导入记录。保留原标签页、旧包和备份，不清理 Safari 数据。

确认下一步后，单独提供 V1.2 测试目录及不同 HTTPS 测试端口（例如 8444）；它是另一来源，使用虚拟账目，不接触 8443 的真实账本，不覆盖 V1.1 ZIP。工具应自动使用测试端口，用户不需编辑脚本。相同 Wi-Fi IP 的现有可信证书可以覆盖该 IP 的不同端口；证书验证失败时停止，不忽略警告。

测试步骤：

1. Mac/iPhone 连同一个私人 Wi-Fi，启动独立测试工具，确认地址端口为 8444 而不是 8443。
2. 在 Safari 普通标签页打开测试地址；新的空账本为隔离测试预期，不用于判断原账目是否丢失。
3. 查看首页单卡概览、输入和识别按钮；依次查看流水、统计，检查雾蓝紫视觉及没有英文装饰标题。
4. 仅用虚拟记录，输入或听写“买菜38元，零食25元”，核对两笔和 63 元合计；修改日期/分类后确认保存。
5. 刷新独立测试页，核对数量、金额、分类和日期；打开统计核对月份，测试手动记账、编辑和取消。
6. 在独立测试来源导出新的测试 JSON，使用不同文件名保存；核对虚拟记录，不覆盖原备份、不在原来源导入。
7. 真机检查系统键盘、听写、Safari 工具栏、底部安全区域、放大文字、多笔展开、长金额和横屏。自然滚动可以接受，不应遮住操作或产生横向溢出。
8. 真正 Safari 的跨版本缓存/存储容器验证须另行使用虚拟数据和独立测试来源；不可据本轮测试解除 DATA-001。
9. 结束关闭测试服务，保留原 8443 网站数据。若需撤销测试 CA 信任，先确认不会影响仍需保留的原 HTTPS 调查环境，不在本轮要求卸载或清理。

本轮在完成自动验证后停止，等待用户确认下一步；不提供覆盖原账本的升级指令。

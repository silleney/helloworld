# iPhone 13 Safari · 免费局域网 HTTPS 验收

此包用于你的 **2015 Intel MacBook / macOS Catalina 10.15.7** 和 iPhone 13。复用已经验收过的 `site` 网页，字节未改动。不需要 Node、npm、Homebrew、付费服务或域名；不部署公网、不增加账户或云同步。

**首次准备需要联网从 GitHub 官方发布地址下载固定版 mkcert（约 5.3 MB）。** 后续启动只用本地文件。工具的 Mac 最低版本/架构、下载校验和、脚本语法和 HTTPS 自动化结果见 [兼容性报告](IPHONE-VERIFICATION.md)。尚未在真实 Catalina/iPhone 上运行，第一次准备会检查你的 Python/TLS，失败会停止，不承诺一定双击即成功。

## 一、先下载和准备

1. 在 Mac 浏览器打开 [iphone-acceptance 分支](https://github.com/silleney/helloworld/tree/iphone-acceptance)，点击绿色 **Code → Download ZIP**。也可 [直接下载 ZIP](https://github.com/silleney/helloworld/archive/refs/heads/iphone-acceptance.zip)。私有仓库需要登录有权限的 GitHub 账户。
2. 双击 ZIP 解压，得到 **helloworld-iphone-acceptance** 文件夹。使用这个新文件夹，原电脑验收包不用删除或覆盖。
3. Mac 和 iPhone 都连接你信任的同一个私人 Wi-Fi，避免访客网、酒店/公共 Wi-Fi。不要配置路由器端口转发或公网隧道。Mac 在测试时保持开机，不进入休眠。
4. 在 Mac 打开“终端”，输入 `cd `（后面一个空格），把整个 **helloworld-iphone-acceptance** 文件夹拖进终端，按回车。
5. 粘贴下面这一行，按回车：

   ```sh
   bash Prepare-iPhone.command
   ```

   首次推荐终端执行，以便看清检查结果。之后也可以双击 `Prepare-iPhone.command`。如果双击被系统策略阻止，可使用上述终端命令；不要关闭 Gatekeeper/SIP、防火墙或证书校验，也不要用 `xattr` / `spctl` 绕过检查。

6. 正常情况下会看到 Python/TLS 信息、官方工具版本、证书生成、公开 CA 指纹，以及类似 **https://192.168.1.8:8443** 的手机地址。记下你实际显示的地址，不使用此例子，也不使用 `127.0.0.1`。
7. Finder 会选中 **iPhone-Test-CA.cer**。这是可以传给 iPhone 的公开证书。不要传任何 `key` 文件，不要把生成文件放进 GitHub、网盘或发送给他人。

如果下载失败、校验和不一致、Python/TLS 不满足要求，或工具执行被安全策略阻止：**停止并复制报错反馈**。不采用 HTTP 手机降级或忽略证书警告来冒充 HTTPS 验收。

证书、CA 私钥、服务器私钥和 mkcert 工具只在你 Mac 的以下个人目录创建，不在下载的 GitHub 文件夹里：

```text
~/Library/Application Support/LittleLedger-iPhone-Acceptance/
```

这是本机个人文件夹位置，不是 Codex 下载链接。不要公开其中内容。脚本不把 CA 加入 Mac 系统信任库，也不需要管理员权限安装软件。

## 二、在 iPhone 安装并信任公开测试证书

1. 在 Finder 中对选中的 **iPhone-Test-CA.cer** 选择 **共享 → AirDrop**，发给你自己的 iPhone。只有这一个 `.cer` 文件需要传输。
2. iPhone 接收并打开，看到“已下载描述文件”或类似提示。只处理来自你自己的 Mac、刚生成的证书。如果不出现下载提示，先反馈具体画面，不安装网上其他证书。
3. 打开 iPhone **设置 → 已下载描述文件**；有些版本在 **设置 → 通用 → VPN 与设备管理**。打开刚收到的证书描述文件，查看证书信息，确认是此次生成的 mkcert 测试 CA，然后点 **安装**。可能要求你的 iPhone 解锁密码。
4. 再进入 **设置 → 通用 → 关于本机 → 证书信任设置**，对这个新安装的测试 CA 开启 **完全信任**。其他证书不要改动。iOS 菜单名称可能因版本略有不同。
5. 如证书详细信息提供 SHA-256 指纹，可与 Mac 准备窗口打印的指纹核对。安装来源必须是你自己的 Mac/AirDrop。

**为什么要做这一步？** Safari 只有信任签发服务器证书的本地 CA，才能验证该局域网 IP 的 HTTPS。你手动授权的是自己生成的测试 CA，不是忽略浏览器警告。持有它的 CA 私钥就能签发被该 iPhone 信任的证书，因此私钥必须保密，测试后移除信任。

## 三、启动 HTTPS 服务并打开小账

1. 双击新文件夹中的 **Start-iPhone.command**。若双击启动有问题，在已切到该文件夹的终端运行：

   ```sh
   bash Start-iPhone.command
   ```

2. 保持弹出的终端窗口打开，它就是前台服务。脚本会检查 Wi-Fi IP、证书有效期、证书链、私钥匹配和权限，然后显示你的手机 HTTPS 地址。
3. 如果 Mac 弹出“是否允许 Python 接收传入连接”，只在你当前私人 Wi-Fi 测试时选择允许。无需关闭防火墙。
4. iPhone 打开 **Safari**，在地址栏输入窗口显示的完整地址，例如 `https://192.168.1.8:8443`（替换成实际值）。必须没有证书警告。不要先在 Mac Safari 打开此 HTTPS 地址：Mac 系统没有被脚本安装 CA 信任，测试目标是已安装证书的 iPhone。
5. 不要打开旧 **Start.command** 来做手机测试，它是原有电脑 HTTP 预览。新服务端口是 **8443**，不会占用电脑验收的 4173。

服务只绑定检测到的 Wi-Fi 私人 IPv4，并拒绝非私人 IP 客户端，只读取 `site` 内的静态文件，不提供目录列表、上传或私钥。它不是带账号的公网服务器；同一可达私人网络的其他设备仍可能访问公开静态页面，所以只在可信私人网短期运行。账目仍保存在各自浏览器，不会通过此服务器上传或共享。

### 防火墙权限和风险

Catalina 的防火墙通常按程序授权，**不等于只放行此脚本或仅 8443 端口**。允许 Python 入站后，其他 Python 进程也可能受该规则影响。

若请求被拦截，可在 Mac **系统偏好设置 → 安全性与隐私 → 防火墙 → 防火墙选项** 查看与此次 Python 对应的条目；只允许所需程序，不关闭整个防火墙，不改变路由器公网转发。设置可能要求 Mac 管理员密码。测试后删除这项临时例外或恢复“阻止传入连接”。若设备被单位策略管理，不绕过策略，先联系管理员或反馈。

## 四、手机人工验收

使用测试数据。手机账本与 Mac 账本不同，这是本地阶段 A 的正常行为。

1. **系统听写**：点击首页输入框，用 iPhone 系统键盘麦克风说“今天买菜花了三十八块，买零食花了二十五块”。听写结束后核对文字，再点“识别账目”。键盘没有麦克风时检查 iPhone 设置 → 通用 → 键盘 → 启用听写。
2. **确认后才入账**：两笔候选可修改；确认前流水没有新增。确认后总額 **63.00**，必要 **38.00**、非必要 **25.00**。
3. **金额与分类**：把零食改成 **12.50**，总额应为 **50.50**。输入“咖啡12块5”，金额应为12.50但分类待确认，取消后不入账。
4. **保存与刷新**：刷新页面、退出 Safari 再打开同一地址，已保存账目还在；编辑、删除、撤销后统计更新。
5. **备份**：导出 JSON、CSV，确认 iPhone“文件”或下载列表中确实保存。重复恢复 JSON 不重复新增。不要清除原数据来做恢复测试。
6. **添加到桌面**：Safari 分享 → 添加到主屏幕。从桌面图标打开，首次联网加载后刷新一次。iOS 不同版本可能为 Safari 和桌面 PWA 使用独立存储，分别核对，不假定自动共享。
7. **离线**：桌面 PWA 中先保存一笔并刷新，再开启飞行模式，确认 Wi-Fi 也已关闭。重新打开/刷新，检查账目并手动保存一笔。系统听写/网页语音是否离线可用取决于设备，不把语音不可用当作本地记账失败。
8. 网页麦克风按钮是可选功能，权限拒绝或 API 不可用时仍应可手动/系统听写输入。识别结果必须由你确认后保存。

iPhone 的 Safari 至少需要 iOS 15.4 对应能力（例如 `crypto.randomUUID`）。本次没有连接实际 iPhone，实机结果需要你反馈。

## 五、停止服务、撤销信任、清理

1. **先备份手机数据**：联网时导出 JSON，确认保存。改变 IP、端口、协议会使用另一个本地账本；旧账目不能被自动认为丢失，更不是已经云同步。
2. 双击 **Stop-iPhone.command**，或在包目录终端执行：

   ```sh
   bash Stop-iPhone.command
   ```

   会校验运行进程的用户、脚本和实例标记，只停止本工具。未运行会提示，不会随机终止 Python 或其他程序。原服务终端应显示停止。也可在服务窗口按 **control + C**（不是 command+C）；关闭该窗口可能留下旧进程记录，可再运行停止脚本。
3. iPhone **设置 → 通用 → VPN 与设备管理**，找到本次测试 CA 描述文件，点 **移除描述文件**，输入解锁密码。若只想暂时撤销，可先在“证书信任设置”关闭完全信任；测试结束建议移除整个描述文件。不要删除别的证书。
4. 回到“证书信任设置”，确认此测试 CA 已移除或不再信任。删除接收的 `.cer` 文件并不能代替删除描述文件。
5. Mac 恢复/删除此次 Python 的临时防火墙入站例外。脚本没有安装 Mac CA 信任，不需要运行 mkcert -uninstall 或修改钥匙串。
6. 双击 **Cleanup-iPhone.command**（会先停止服务），或运行：

   ```sh
   bash Cleanup-iPhone.command
   ```

   提示时输入 **DELETE** 并回车，才删除本工具个人目录中的 CA/服务器私钥、证书和工具。不删除网页或浏览器账目。删除不可撤销，下次准备会生成新 CA，iPhone 需要重新安装新证书。无需继续测试时，也可删除本包文件夹。

## 六、遇到问题如何处理

| 现象 | 安全处理 |
|---|---|
| GitHub 或 mkcert 下载失败 | 保留终端报错并反馈，不能绕过 TLS 或校验和 |
| Python/TLS 检查失败 | 停止并反馈 Python/SSL 版本，不安装旧 Node、不降级 HTTP |
| 系统阻止工具启动 | 反馈具体提示，不关闭系统安全保护或清除安全标记 |
| 手机打不开 | 检查同一私人 Wi-Fi、电脑未休眠、8443 服务前台运行、防火墙对应权限；访客网可能隔离设备 |
| 证书警告 | 不继续；核对手机信任、实际 IP、设备时间、证书是否过期 |
| “Wi-Fi IP changed” | 先停止服务，重新执行 Prepare 生成匹配新 IP 的证书，再启动；同一 CA 无需重复安装，除非之前已清理 |
| 浏览器中账目变少 | 先核对地址/浏览器/PWA 是否变化，使用自己的 JSON 备份恢复，不清空旧数据 |
| 端口占用/旧进程记录 | 运行 Stop-iPhone.command，只停止此工具；仍报错就反馈，不随机杀进程 |

没有永久后台服务，没有购买或开通任何云资源，测试结束停止即可。服务日志只涉及静态页面请求，不包含账目；账目在 iPhone 浏览器内，必须自行备份。

# 小账 V1.3 体验打磨：审计、验证及真机步骤

日期：2026-10-10（北京时间）。分支 v1.3-flow-polish，基础 V1.2：2780e5d897dfb32c457a3afad0f96ec1c575ff57。

## 修改前只读审计结论

手机 textarea 原为默认 64px / 聚焦 110px 固定高度，长听写缺少内容自适应；待确认项原始四字段全部展开；parseExpenses 从金额前缀去除日期和结尾“花了”等，未清洗明确重复。桌面/手机共用 Draft 和存储，适合只更改手机展示，不复制业务状态。

无单位的“今天买菜花了38”“买菜，买菜花了38”仍不能作为明确金额，V1.3 不扩展金额格式或猜测金额。该输入会保留并提示；描述清洗仅对可识别金额前的描述执行。

## 文件与行为

src/App.tsx：手机文本按内容自适应，默认 64px、聚焦最小 96px，最多 240px；键盘缩小 visualViewport 时进一步限制高度，超出可内部滚动。窗口改变为桌面时移除内联高度。成功识别仍收起键盘。失焦不立即改变高度，避免按钮在触摸点击中途移动；识别执行后重新测量，键盘关闭时不抢先收缩。手机候选摘要显示描述/金额/待确认分类，点击单笔展开原字段，同一时间展开一笔；手动新增和历史编辑直接展开。保存校验失败自动展开出错项，不写入任何部分账目。

src/style.css：仅手机启用摘要与隐藏/展开；桌面字段容器 display:contents，不改变原网格，摘要按钮不显示。

src/domain.ts：仅逗号分成恰好两段且两段去空格后完全一致时，折叠为一段；不删除子串或无逗号重复，不处理三段以上，不改写含义不确定的结构。既有日期/金额解析逻辑继续保留。

tests/domain.test.ts：12 项新增描述边界测试。tests/e2e/flow-polish.spec.ts：长输入/内部滚动/缩短，三笔摘要/展开字段/准确合计/分类/日期/最终保存和刷新。helpers.ts 与原两份 E2E 文件仅补充“先展开再操作”动作，原断言和业务覆盖保留。tests/verify-v13-screenshots.mjs：对照原 V1.2 ZIP 的截图验证。没有修改数据库、backup 格式、依赖、PWA 配置或旧验收 ZIP。

## 风险及真机验收（仅独立虚拟测试来源）

这些 Chromium 检查不能证明真实 iPhone 键盘、听写光标、visualViewport 和内部滚动行为。刷新会恢复候选内容但折叠为摘要，展开状态不持久化。保守清洗保留更多口语是有意边界。

本轮没有改动原 8443 页面、网站数据或现有独立验收包。提供 V1.3 独立包后，继续在虚拟测试来源 8444 进行：

1. 保留原 8443 环境和备份，不清理 Safari 数据、不卸载 PWA、不导入原备份。仅更新独立 8444 测试包的页面。
2. 连续听写多行长文本：框按内容扩展，达到上限后可内部滚动，最后一行可检查，键盘打开/关闭后按钮可点击。删短文字后应缩回，Safari 工具栏变化不应截断操作。
3. 输入“今天买菜，买菜花了3块5”，检查候选描述“买菜”、金额 3.50；“咖啡，咖啡12元”只保留“咖啡”；“买了两份买菜礼包38元”应完整保留礼包名称。
4. 无单位“今天买菜花了38”应提示未识别且保留原文，不生成账目。
5. 输入“买菜¥38，零食¥25，打车¥20”，默认三个摘要、合计 83.00；确认前最近记录不增加。点一项修改描述、金额、日期、分类，合计同步更新，切换项时原修改保留。
6. 未确认分类的项必须由用户选择；保存失败应展开错误项，不能部分保存。手动新增、历史编辑四字段直接可编辑。取消不保存、不清原文。
7. 最终确认、连续点击、刷新、JSON 虚拟备份与恢复；核对只保存一次、金额/分类/日期一致。
8. 桌面查看原布局和展开表单。放大手机页面、多笔展开时允许自然滚动，不应出现横向溢出或底部遮挡。

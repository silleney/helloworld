# 小账 V2.0 独立云测试页

## 范围与地址

当前仅云基础交互验证，不替换已上线 little-ledger-4tz.pages.dev。日常静态生产分支 v2.0-pages-static 和 main 不修改。用户已关闭旧 Pages 项目的自动预览部署；推送 v2.0-cloud-ledger 仅保存源码。本测试建议另建免费 Pages 项目 little-ledger-cloud-test（可用性由控制台确认），将 v2.0-cloud-ledger 作为新项目的发布分支；这不意味着把云测试版发布为日常正式账本。不要改旧项目的生产分支、构建或环境变量。

独立入口 cloud-preview/index.html；独立配置 vite.cloud-test.config.ts；输出 dist-cloud-test。普通 npm run build 仍只构建原本地 App。新测试页面不注册 Service Worker、不安装新的 PWA，不能用于离线冷启动；首次加载/刷新后登录需要联网，登录后的离线队列可保留待同步操作，恢复网络再重试。认证令牌只在内存，刷新需重新登录。独立数据库 little-ledger-cloud-v1 按项目/账号/账本隔离；不读取、改写、删除 little-ledger-v1。新地址也不会继承 8443/8444/日常 Pages 的浏览器存储。

本页面只用于虚拟账目，不实现正式迁移、云冲突强制覆盖、自动后台同步、JSON导入或账户恢复。原正式页面、视觉和交互保持不变；测试页使用简洁雾蓝紫表单，不代表重新设计日常页面。

## Supabase 已由用户确认的配置

little-ledger-dev（Singapore Free）：迁移成功，4表RLS开启；anon无私有schema/table权限；authenticated只可SELECT，不能直接写表；3业务RPC仅authenticated可execute，两个definer有固定空search_path；无业务视图。Data API 暴露public，不暴露ledger_private。控制台橙色函数图标是自定义授权提示，保存会覆盖授权：不能勾选或保存以“修复0 exposed”。公开注册关闭，匿名登录关闭，邮箱登录开启，A/B测试账号由管理员auto-confirm创建。真实REST权限仍待验收。

公开配置 src/cloud-preview/config.ts 仅包含用户批准的项目URL和sb_publishable_ key；这些会公开在浏览器构建中，属于预期。没有service_role、secret、密码或访问令牌。CSP只允许连接该项目。密码由用户自己输入，测试代码不存储密码，不要求向Codex发送。浏览器密码管理器是否保存由用户自行决定。

## 用户部署步骤（聊天一次指导一步）

1. 回到 Workers & Pages 项目列表，选择 Create application → Pages → Connect to Git。使用现有GitHub授权，仅选择silleney/helloworld；若页面指引不同先截图，不授权所有仓库。
2. 新项目名建议 little-ledger-cloud-test；生产分支选v2.0-cloud-ledger，不能main，也不能v2.0-pages-static。此处Production仅指新测试项目的发布分支，不改日常站点。
3. Framework preset选None；Root directory留空；Build command：`npm run build -- --config vite.cloud-test.config.ts --target=safari15.4`；Build output directory：`dist-cloud-test`。Node变量`NODE_VERSION=24.19.0`。无需录入任何Supabase Secret，不添加数据库binding或Functions。保留锁文件，不升级依赖。
4. 点击部署前先向Codex核对配置截图；部署后记录新项目固定HTTPS网址。在新项目Branch control关闭其他预览分支自动部署，所有后续发布先本地测试。不要使用日常站点测试云登录。
5. 部署后检查真实HTML/CSS/JS Content-Type、no-store/CSP响应头、手机无证书警告。若CSP阻止连接先核对精确项目URL，不能放宽到*或禁用浏览器安全。

## 第一次登录与测试账本

登录A，密码只输入本页，不发聊天。页面显示用户ID和账本ID；账本ID固定使用用户UUID，两设备同账号使用同一账本；本页首次点击“建立虚拟测试账本”生成空云账本，重试复用同ID。仅适用于尚无既有不同ID个人云账本的测试用户；如果出现owner唯一约束错误，停止并检查，不能删除旧云账本或自行重建。

登录不会自动创建账目或云账本，也不会自动上传旧数据。已建立的账本点击“同步与重试”读取；未成功读取时不展示正常的0账本。只可用“建立虚拟测试账本”按钮建立本人账本。

## 验收顺序

1. A输入“买菜¥38，零食￥25”，识别2笔，确认前云端无记录；可以核对描述、金额、日期和分类。确认后看到2笔63.00及“云端已确认”提示。手动记账、编辑、删除正常。
2. iPhone/电脑同新地址、同A账号登录并同步，字段/金额/ID一致。点击编辑后用另一个设备先保存，旧设备提交必须显示冲突，不自动覆盖。选择“保留云端版本”前明确确认；原请求保留为discarded审计，云端记录不被替换。
3. 已登录并联网同步后，断网保存一批：明确显示本机待同步，不显示云端成功；暂停后续新提交与不完整JSON导出。恢复网络点击“同步与重试”，只新增一次。刷新后需要登录，原pending仍保留，重试同操作ID。
4. 账号A退出后登录B，不能看到A缓存；B建立自己的虚拟空账本。将A账本ID填入隔离测试框，检查跨账号读取/写入；必须42501拒绝。写检查用不存在ID、修订0，不要求删除有效记录；若意外放行，只可能生成操作日志，测试应判失败并停下。
5. “检查匿名访问”仅使用公开key，不发用户token；必须明确42501拒绝。网络错误、404/密钥错误不当作权限通过。实际Supabase错误差异需检查，不能放宽权限解决。
6. 待同步/冲突全部处理后，导出V1格式虚拟JSON，检查ID、描述、分、分类、日期、source、created_at、updated_at；不含revision/deleted，仅导出未删除且已确认记录。当前没有恢复入口，云备份恢复在下一轮隔离工具验证，不导入真实账目。
7. 离线超时、会话过期/撤销、Safari存储限制、主屏幕生命周期及真正云服务暂停均需真实环境验收；本页不保证离线免登录。

## 自动化与限制

`npm test`：120通过（既有98+云22）。独立构建Safari15.4通过；Cloud UI E2E使用虚拟REST服务和虚拟密码，真实数据库权限由上一轮隔离PostgreSQL验证，不能把浏览器模拟接口称为真实Supabase通过。本轮交互覆盖登录、确认、编辑删除、V1导出、token不落盘、响应丢失/重复点击/重开、断网续传、退出账号隔离、匿名/跨账号拒绝、明确冲突处理、双设备一致及过期修改冲突；390手机宽度无横向溢出。没有向真实Supabase发认证或写请求。

保存先stage落盘再请求，网络15秒超时仍当结果未知，重试同ID。一次只允许一批未确认操作，简化离线依赖；不能说已完成复杂实时同步。冲突放弃只处理明确server conflict，未知结果pending不能取消。客户端不清理操作日志或网站数据。Supabase本地logout撤销刷新会话，access JWT可能到期前仍有效；权限拒绝仍需DB控制。

## 回退与停止

先退出测试账号，保存虚拟备份，停止使用新测试站即可。不要清理Safari数据，不改变旧项目或旧数据库。必要时暂停新项目自动发布；云写入故障采用已有rollback-disable-cloud.sql，由用户确认在dev项目执行，仅撤销写权限、不删数据。测试站回滚不回滚数据库；无需再次运行建表迁移。

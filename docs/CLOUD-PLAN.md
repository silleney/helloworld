# 国内免费部署与云同步研究、阶段 B 方案

记录日期：2026-10-10。阶段 A 已采用无需云资源的本地架构；本次没有开通服务、购买域名或使用收费 API，未进入阶段 B。

## 本次研究的证据与限制

当前环境访问以下官方文档入口时，网络代理返回 `403 Forbidden / Tunnel connection failed`：

- 腾讯云 CloudBase 文档：<https://docs.cloudbase.net/>（尝试读取计费与静态托管页面）。
- 阿里云官方 ESA 文档：<https://www.alibabacloud.com/help/zh/edge-security-acceleration/esa/user-guide/esa-pages>。

因此**未核实当前免费额度、有效期、账户申请资格、续费处理、免费域名及备案政策**，也未完成大陆真实网络测量。以下是候选方案和明确的核实清单，不是永久免费承诺或推荐立即开通的依据。访问被策略拦截不代表供应商服务不可用。继续在线研究需在环境设置允许 `docs.cloudbase.net`、`cloud.tencent.com`、`www.alibabacloud.com` 和 `help.aliyun.com`；本次未改动网络配置。

## 候选比较

| 需要验证的条件             | 腾讯云 CloudBase（第一候选）                                | 阿里云 ESA Pages（第二候选）                              |
| -------------------------- | ----------------------------------------------------------- | --------------------------------------------------------- |
| 免费资格、有效期、到期处理 | 待官方控制台/条款确认；重点核实新用户限制及到期是否删除数据 | 待确认免费层、试用期、到期处理                            |
| 静态托管与 HTTPS           | 待确认免费额度及资源/流量计费                               | 待确认 Pages 额度、构建次数、流量与 HTTPS                 |
| 默认域名在大陆可访问性     | 待确认访问限制、是否仅测试用途、是否必须独立域名            | 待确认默认域名与大陆节点的实际可访问性                    |
| 域名及 ICP 备案            | 待官方确认，无域名时是否能长期合法访问                      | 待官方确认不同节点/域名模式的要求                         |
| 数据库、认证与用户隔离     | 分别确认认证方法、数据库读写/容量、权限规则与出口费用       | Pages 本身不能被假定包含数据库/认证；需另核实免费数据服务 |
| 零费用边界                 | 确认免费额度可硬限额，超额不自动产生费用                    | 确认超额和关联服务都不会自动付费                          |
| 可迁移、可退出             | 核实可完整导出、退出前备份及到期宽限期                      | 核实数据服务可完整导出及退出方式                          |

当前结论：**尚无已验证、无需购买域名、国内稳定可访问且长期零费用的完整云同步方案。** 不应先开通资源再假定免费。需要以用户账户可见的实际套餐条款为准，截图/导出条款记录日期与有效期，并在真机测试。

## 进入阶段 B 的准入条件

用户确认进入下一阶段后，先做不涉及付费开通的验证：

1. 查阅实时官方条款，确认用户资格、免费期限、数据库存储/读写、静态托管/流量/构建、认证用户数、域名及到期行为。
2. 核实能否禁止自动续费、按量超额和关联资源计费。如果不能保证不产生额外费用，停止方案实施并说明。
3. 在无 VPN 的大陆 Wi-Fi 与蜂窝网络，用实际 iPhone 13 Safari 和电脑测试默认 HTTPS 域名、登录、数据库读写、统计、静态资源及语音降级。
4. 确认没有必须付费购买的域名；确认服务方式对应的备案条件。不要把海外可访问等同于大陆可访问。
5. 确认后台导出/迁移和免费到期备份流程。只在全部条件得到证据支持后接入。

如果无法找到可靠免费方案，保留本地 PWA，以 JSON 导出/恢复手动搬运账本。这不是实时同步；不要让两台设备同时修改再盲目合并。可继续研究已有设备自托管，但其网络、电力、HTTPS、认证和维护成本不等于零，也需要用户另行确认。

## 云同步接入设计（未实施）

- 保留 `amount_cents` 整数金额与 `spent_on` 本地日期；增加 `user_id`、服务端版本号、服务端更新时间、删除标记。业务逻辑仍从数据适配层访问。
- 认证采用候选服务正式支持的方法。每次读取和写入都由服务端强制检查当前身份，不能仅靠前端过滤 `user_id`；管理员密钥不得进入 Vite 构建或前端变量。
- 本地 IndexedDB 按已验证的用户 ID 建立命名空间。退出清理界面中的上一用户数据，未认证的本地账本需独立保存。迁移前导出 JSON，用户确认归属后执行一次性、可重试的批量迁移。
- 离线新增先写本地与待同步队列，同步时以条目 ID 和操作 ID 幂等去重。时间戳不能独自决定冲突胜者。
- 编辑/删除提交基础版本；服务端使用条件更新。版本不符时展示两份内容由用户选择，禁止无提示覆盖。删除保留 tombstone，避免另一设备重新上传导致“复活”。
- 网络失败保留队列并显示“未同步”，认证过期先重新登录；设置退避和重试上限，不将本地成功冒充云端成功。
- 首轮验证：A 设备新增→B 设备读取；B 修改→A 更新；离线新增/重连；两端同时编辑；删除与旧设备回传；不同账户交叉读写必须被拒绝；备份及云端完整导出一致。

验收结果必须分别报告本地成功、同步成功和真实大陆设备验证；候选方案、账户开通、部署和真实数据迁移均未在本次执行。

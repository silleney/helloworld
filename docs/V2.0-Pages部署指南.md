# V2.0 阶段 1：Cloudflare Pages 静态部署

基线：v1.3-flow-polish / 0bfffc4983bbbc6b37e1d637fa9317c940187a1a。部署分支：v2.0-pages-static。main 不部署、不修改。阶段 1 不包含认证、云数据库、同步或真实账目迁移。

## 待用户逐步完成

1. 登录 https://dash.cloudflare.com/ 。选免费方案，不绑定支付方式。完成后返回聊天，下一步再指导。
2. 创建 Pages 项目，选择 GitHub 集成。GitHub 授权选择 Only select repositories，仅 silleney/helloworld；不要选 All repositories。若账户策略不允许最小授权，先反馈。
3. 项目名称建议 little-ledger-silleney，是否可用需控制台验证。生成的 pages.dev 地址要作为固定地址，不以每次构建的预览地址作为日常账本。
4. Production branch 必须选 v2.0-pages-static，不能选 main。构建命令 npm run build -- --target=safari15.4；输出目录 dist；根目录留空（仓库根）；Node 环境变量 NODE_VERSION=24.19.0（与本次验证环境一致）。使用项目现有 lockfile，不升级依赖；无需业务密钥。
5. 提交部署前核对上述值。仅发布 dist，不发布仓库根、acceptance ZIP 或证书工具。GitHub 自动构建不能把源代码根当作发布目录。
6. Branch control 中禁止其他预览分支自动部署（None 或排除全部，按控制台实际选项）；保留指定生产分支的构建。不要选 All branches。任何生产分支 push 都可能更新站点，后续只推送经验证的发布内容。首次部署后验证实际配置及日志。

## 技术检查

Vite 默认根路径与 start_url=/ 适合 Pages 根域名；无需子路径 base。页面内部导航用 React 状态，没有服务器 API 或深层路由需求。现有 manifest、Apple 图标、standalone、Service Worker 及更新提示保持不变，包括既有图标颜色；不重做界面。public/_headers 会进入 dist，首页、HTML、Service Worker 和 manifest 使用 no-cache 允许校验更新，哈希 assets 长缓存；未增加 Pages Functions。缓存头在真实 Pages HTTP 响应上仍需验证，Cloudflare 配置可能影响最终响应。

## 真机验收（仅虚拟账目）

新域名是独立存储来源，不继承 8443/8444 数据。Safari 标签页和主屏幕容器是否共享数据必须分别实测。先不导入真实 JSON，不删除旧网站数据或旧 PWA。

- 使用固定 HTTPS 地址，无证书警告，页面为 V1.3 摘要式确认。
- Mac 关机，iPhone Wi-Fi/移动网络均可打开；添加主屏幕后正常启动。
- 首次联网加载完成后，离线冷启动并记录虚拟账目，刷新/重新启动仍保留；首次离线访问不能保证可用。
- 买菜¥38，零食￥25，打车20元得到3笔83.00；确认前不入账，编辑分类/金额/日期正常，保存不重复。
- 流水、统计、删除及撤销，长听写与键盘，JSON虚拟备份恢复。
- 后续同一固定域名更新时，输入与待确认不丢失，更新后全部原虚拟记录逐字段一致。不能清空缓存或网站数据来解决更新。
- 浏览器读取失败必须报错，不能假装正常空账本。静态托管不是云同步；数据仍可能因浏览器清理、设备损坏而丢失，定期保存JSON到设备外。

## 回退

保留旧分支、旧验收包和有效 JSON。需要回退时先备份新域名数据，暂停生产自动部署，再在 Pages 选择此前验证过的部署回滚；确认下次 push 不会覆盖回滚。保持同一固定域名；回滚网页不回滚 IndexedDB，也不能自动找回已删除记录。不清除 Safari 数据。

## 费用与授权

本阶段只使用免费静态托管，不购买域名/服务器，不创建 Supabase、不绑定支付方式。如控制台要求付费、过度授权或与文档不符，暂停反馈。实际站点地址、项目名和账号配置在用户登录后确认，本文件不声明部署已经成功。
